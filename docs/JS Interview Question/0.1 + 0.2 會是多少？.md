JS 當 0.1 + 0.2 會出現非預期的結果 0.30000000000000004，這是因為 JavaScript 使用 IEEE 754 標準來表示浮點數，而這個標準在表示某些十進制數字時會出現精度問題。如果是面對金融類的產品要特別留心處理。

---

> 這邊要口語化你的重點給考官聽：
「因為 0.1 和 0.2 沒辦法用二進位精確表示，電腦只能近似儲存，所以加起來會有一點點誤差。」
「這是所有用 IEEE 754 浮點數的語言都會遇到的現象，不只 JavaScript。」

---

## 那怎麼解決比較好？（考官問
可以操作 build-in 的 `toFixed()` 方法來解決這個問題，這個方法會將數字轉換為指定小數位數的字符串，然後再轉回數字。

```javascript
const result = (0.1 + 0.2).toFixed(2); // "0.30"
console.log(parseFloat(result)); // 0.3
```

或是 `toPrecision()` 方法：

```javascript
const result = (0.1 + 0.2).toPrecision(2); // "0.30"
console.log(parseFloat(result)); // 0.3
``` 

簡單寫一下他們的差異：

這邊 `toFixed()` 是固定小數點後的位數，無法用科學記號表示。
```javascript
let num = 123.456;
num.toFixed(2); // "123.46"
num.toFixed(0); // "123"
num.toFixed(5); // "123.45600"
```

而 `toPrecision()` 則是指定總位數（包括整數和小數部分），以及可能用科學記號表示（exponential notation）。
```javascript
let num = 123.456;
num.toPrecision(2); // "1.2e+2"
num.toPrecision(3); // "123"
num.toPrecision(5); // "123.46"
```

補充說明
* toFixed 適合顯示金額、分數等需要固定小數位的場合。
* toPrecision 適合科學計算、需要控制總有效位數的場合，位數少時會自動用科學記號

一句話記憶法：  
toFixed 是「小數點後幾位」，toPrecision 是「總共幾位有效數字」
